# C / D 合集剪辑

共用执行器与完整参数说明见 [character-showcase-editing](../../../../skills/character-showcase-editing/SKILL.md)。本页区分历史已记录规则和方便新项目启动的默认值。

## 两种模式

| 模式 | 顺序 | 图片动画 | 视频处理 |
| --- | --- | --- | --- |
| C 原图→动态视频 | 图1→视频1→图2→视频2 | 原缩放/模糊曲线，结束后保持 | 只保留自身运动，不追加图片缩放 |
| D 视频合集 | 视频1→视频2→视频3 | 没有图片段 | 统一画布、时间轴、转场与配乐 |

视频和图片必须用显式路径，C 的每对共用 `pair_id`。不要按“最新文件”或模糊编号选中旧版/弃用版；用户换顺序时将图与对应视频一起移动。缺失文件要补齐，不能自动补入其他角色素材。

## 新项目默认值

- 输出1080×1920、60fps，SAR1，yuv420p，时间戳从0开始。
- 方形素材采用同源模糊背景与居中前景；同画幅竖屏片段可用 `layout.mode=plain`，无须重复加背景。
- 非方形素材按 `fit=contain` 或用户指定的 `cover` 保持比例，不压成正方形。C 对应图/视频使用同一布局、对齐和前景比例。
- C 默认图片段360帧（6秒），`scale_speed=1`；D 没有静图。视频默认 `speed=1`。
- 全部相邻边界30帧交叉溶解，结尾30帧音画淡出，淡出在总长内完成。用户要求硬切时 `transition_frames=0`。
- 用户提供 BGM 才使用 `audio.mode=bgm`，基线 `gain_db=-7`、`source_start_seconds=0`、`output_start_seconds=0`；没有 BGM 时 `silent`。是否循环在 manifest 中显式记录。

保留自然声时用 `audio.mode=source`；自然声叠加 BGM 时用 `source+bgm`，`source_gain_db` 控制原声（默认0），`gain_db` 单独控制 BGM。共用渲染器对变速片段同步处理 `atempo`，转场使用对应 `acrossfade`，无声片段和 C 类静图段补等长静音。用户要求保留原声时不要选择 `silent` 或 `bgm`。

## 历史 C 参数

工程包中的 C v7 实际采用：图片272帧、缩放4/3倍速、视频1.1倍速、全边界0.5秒溶解、尾部0.5秒音画淡出。模糊背景236%与模糊40，清晰视频前景104%，原图动画终点也是104%。背景与前景一起溶解。

原图片缩放曲线（60fps）：

| 相对帧 | 缩放 | 保存的切线值 |
| --- | --- | --- |
| 0 | 312% | -6.120207911535838 |
| 123 | 222% | -27.796610169488954 |
| 186.268 | 222% | -27.796610169488954 |
| 310.733 | 104% | -9.562927856583157 |

曲线使用归一化区间 `u` 的 cubic Hermite；保留这些历史传入的切线值，不再额外乘帧间距。前景模糊45→0，结束于91.117帧。4/3倍速只作用于缩放，模糊没有同步加速；数学缩放终点为233.04975帧，272帧图片段中保留38帧端点保持。

这些特例不自动继承到新项目。历史 BGM 从源第1秒读取，但成片第0秒立刻播放；不是先静音1秒。历史脚本头部残留“hard cuts”注释，实际代码与 manifest 是全边界溶解。历史素材为方形，旧脚本强制方形缩放不能推广到任意长宽比。程序与 Premiere 的模糊、重采样和羽化不保证像素相同。

## 时长与转场

先按裁切与速度求每段实际时长 `di`，再按输出 FPS 量化帧数。M段、转场T秒时：

```text
elapsed = d0
每加入下一段：offset = elapsed - T
              elapsed = elapsed + di - T
总长 = sum(di) - (M - 1) * T
```

每段需要足够转场余量；不能用负 offset 或过长重叠掩盖短素材。硬切时总长为各段相加。C 的图/视频都是独立段，不能只按配对数量扣重叠。

图转视频突然缩小时，先核对两侧前景104%与居中规则一致，而不是盲目改成106%。H3产生的姿势或颜色变化需回到源片定位，不能都当成缩放问题。

## 执行命令

从仓库根目录运行，示例路径相对各自 manifest。先将示例复制到用户项目并替换所有素材路径、源实际时长和输出名：

```bash
python3 skills/character-showcase-editing/scripts/showcase.py path/to/edit.json --plan
python3 skills/character-showcase-editing/scripts/showcase.py path/to/edit.json --check
python3 skills/character-showcase-editing/scripts/showcase.py path/to/edit.json --render
```

`--plan` 可以含待生成路径，只展开计划并报告存在性；`--check` 只查配置、文件存在及输出不冲突；只有 `--render` 启动媒体处理。`source_duration_seconds` 必须在实际生成/剪辑时由媒体信息填入，示例里的10秒不能当作已验证的源时长。

新成片不得覆盖已有输出。编码成功后记录实际时长和输入清单；没有播放或视觉检查时写“已渲染，待用户验收”，文件检查通过不能替代画面验收。
