# 角色视频合集

原创配方：**Shenrui Ma（四倍体果蝇）**。交付成片、实际输入清单和生成记录。完整链路是“角色设定 → ComfyUI 参考图/首帧图 → 独立 H3 片段 → 合集剪辑”。

## 按顺序执行

1. **接住一句话。** 沿用用户指定角色、图片及已有项目设定。只说角色名也可以开始：默认三个独立镜头、固定服装、轻微自然动作，每段目标约10秒，最终1080×1920、60fps。默认 D 视频合集；明确要“原图再动起来”时选 C。把默认值写入当前项目计划，不用逐项追问。没有角色且无项目身份时，仅询问角色；不要擅自选备用人物。
2. **分清新生成和重剪。** 用户明确要剪已有视频、复用画面或只换音乐时，建立显式素材列表后跳到后期。新的角色需求必须生成对应素材。不要用旧视频冒充新结果，缺少输入也不要偷偷换版本。
3. **准备环境。** 读[生成链路](references/generation.md)，通过关联 Toolkit 获取 `h3-i2v-live-portrait`，先确认本地 ComfyUI、模型和节点可用；用户指定服务器才走远程连接与文件传输。新建项目目录，源素材只读。需要适配时核对当前安装版本的真实节点，不能编造节点或直接替换成 Ref2VA。
4. **生成图。** 调用 [ComfyUI 参考图 Skill](../../../skills/comfyui-reference-images/SKILL.md)，准备身份参考与每镜头首帧。按现有模型选择 SDXL/Anima，缺模型沿用该 Skill 的 Civitai/Hugging Face 发现、兼容性核对及下载流程。使用[图像提示词](prompts/reference-image.txt)，先完成一张，再批量完成其余；用户自己的可用首帧直接登记，不强制重生。
5. **生成动态片段。** 使用[动作提示词](prompts/i2v-motion.txt)，逐图绑定首帧 I2V，保存每条 `prompt_id`、工作流、seed 和输出文件。各镜头独立，不接前一条的 latent，不套动作重演参考视频。先确认首条技术结果再继续；断线查询原任务，失败只重试该镜头。不要对既有 H3 参数或输出帧数做未经证实的假设。
6. **锁定剪辑清单。** C 模式记录 `图1→视频1→图2→视频2`，每对共用 `pair_id`；D 只列视频。按真实媒体信息填入源时长、裁切、速度及相对路径。用户调整顺序时整对移动。按[剪辑规则](references/editing.md)选择布局与音频，不套图片动画到视频上。
7. **执行后期。** 读取 [共用剪辑 Skill](../../../skills/character-showcase-editing/SKILL.md)，先 `--plan`，再 `--check`，最后在用户要求生成成片时 `--render`。未明确要求保留原声时，默认去原声；未指定 BGM 则无声。要求保留原声时选择 `source`，同时配乐则 `source+bgm`；源声按变速同步处理和跨段淡化，无声段补等长静音，不静默丢掉用户需要的声音。
8. **交付。** 编码成功后才标记已生成；保留原始图、原始视频、编辑 manifest 和成片。区分文件检查、实际推理、实际渲染、画面/声音验收。用户只要求检查文件时只做配置和路径检查，不调用视觉、播放、图像/视频推理或渲染。

## 加载顺序与完成条件

- 只剪已有素材：直接读 `references/editing.md`；无须启动 ComfyUI。
- 从文字开始：先读 `references/generation.md`，参考图由 ComfyUI 完成；仅在依赖可用时执行 H3。
- 文件、图像或节点缺失就明确报告缺项；不能以计划、占位文件或“队列已提交”代替成片。
- 关联 H3 图包含24→60fps的 RIFE；保留插帧前后的来源关系。后期统一为60fps本身只是重采样，不是再次插帧；默认不另加超分或覆盖原片。
