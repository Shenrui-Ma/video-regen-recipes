# 案例与验证边界

配方整理自 **Shenrui Ma（四倍体果蝇）** 已完成的泳装动态合集。这里保存归一化方法和参数，不分发历史整段视频、背景音乐或完整个人素材库。

| 证据 | 能确认的事实 |
|---|---|
| 8 段项目要求、渲染脚本和 manifest | 素材顺序、具体裁切、倍速、0.2 秒转场、运动画面开场模糊、保原声及 BGM -12dB |
| 2026-08-27 的最终交付记录 | v4：62.150 秒、3729 帧、1080×1920、60fps、SAR 1:1；H.264 约 100.02Mbps、AAC 48kHz 双声道；历史记录称完整解码通过 |
| 与实际 seed 对应的 8 份 H3 API 图 | `first_frame` 图生视频、864×1344、20 步、原生声音、RIFE 24→60；10 秒与15秒段采用不同 length |
| 4 张原始首帧 PNG 中的 ComfyUI 文本元数据 | SDXL 生成来源及保存工作流节点；包括多输出分支，不能声称全部节点都运行过 |
| 历史超分与剪辑文件名、manifest | 案例用了 RTX VSR 3× ULTRA 再剪辑；该步骤与补帧不同 |

新公共模板补齐了统一的 ComfyUI 首帧入口、角色槽替换、固定 Toolkit 工作流关联、按镜头恢复与文件检查。它们是根据已发生链路整理的可复用实现，**本次没有重新生成新角色、执行图片/视频推理、观看媒体或做视觉验收**。历史报告中的“解码通过”也不等于这次重跑了检查。

历史与新默认的差别：

- 默认动作提示词做了角色无关的改写；第 4 段可在普通角色与机械角色之间切换配件描述。不会保证新模型/种子产生逐帧相同动作。
- 历史图存在不同 attention 加速配置；以固定 Toolkit 的实际节点依赖为准，不能把某台机器的配置当所有用户都有。
- 历史部分首帧无可读取的 ComfyUI 元数据；新默认明确通过 ComfyUI 生成并保存其调用记录，不能倒推所有旧图的完整来源。
- 本模板使用 8 段 v4 的 62.15 秒节奏。另有 7 段约 60.9167 秒、末尾 2 秒黑场的旧例，属于不同成片，不混用参数。
- 新默认不强制 RTX VSR 或 100Mbps，也不自动使用原案例歌曲。改变编码质量、超分或音乐会改变最终文件，但无需重跑 H3。

首帧身份有明确教训：历史上发生过“参考图仍是另一角色、只在 H3 提示词中换名”导致身份未替换。因而本模板把身份检查放在首帧生成阶段，先做对图片，再提交视频。
