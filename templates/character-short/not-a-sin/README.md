# XX不是罪过 · 本地 H3 角色重演配方

**把自己的角色放进熟悉的动作与音乐节奏里，做一支完整的「XX不是罪过」。**

这是 Video ReGen Recipes 收录的第一份作者原创二创配方，由 **Shenrui Ma（马深睿）**在《银狼不是罪过》的多轮制作中设计、取舍并迭代形成。它以《DeepSeek不是罪过》的制作分享为启发，但不是该作者教程的直接翻译或模型名称替换：本配方采用自托管 MiniMax H3，并围绕慢速动作参考、整链续接、精确时间线和原音乐回装重新组织制作。

「原创」指本仓库作者的配方设计与迭代整合，不指发明 H3、RIFE、Motion Context，亦不主张原歌曲、原视频、角色或动作属于本仓库。见[来源与署名](sources.md)。

> **状态：配方文档已收录；银狼案例有历史成片；公开执行包整理中。**
> 当前提供完整制作说明、参数化提示词、运行契约与历史证据，不附带可直接导入运行的完整续接工作流或一键执行器。不能仅靠安装普通 H3 节点完成全部续接步骤；具体缺口见[工作流说明](workflows/README.md)。新角色、新设备和公开包尚未完成端到端复现，不标 stable。

## 想做出的效果

一位角色跟随参考片的动作、景别变化、快速切镜和音乐节奏完成表演。允许更换主演及其固定服装，尽量保留参考的构图、背景亮度与动作时序。首个历史案例为银狼，原速母版约 **97.6 秒**；此时长来自该参考片，不是模板固定时长。

- **要保留**：动作与镜头的时间结构、单主演关系、节拍和原音乐时间轴。
- **可以改**：角色身份、固定服装、参考片范围、经验证的输出规格和后期档位。
- **另作变体**：跟随源片逐段换装、重新编舞、更换场景或歌曲。需要额外资产和重新对时，不能只改一个名字就视为成功。
- **不承诺**：逐像素只换人物、零背景漂移、手指完全一致、任意多人片通用、任何显卡直接运行。

特别注意：银狼基线锁定**同一套角色服装**。参考时间表中的浴衣、睡衣等标签是源片定位标签，不表示银狼成片已经验证了对应换装能力。

## 一眼看懂流程

```text
角色参考图 + 驱动视频 + 完整音乐
                 ↓
      按源片绝对帧号建立分段表
                 ↓
     RIFE 补帧 → 制作 0.5×动作参考
                 ↓
      拆成 H3 可承载的生成子段
                 ↓
角色图 + 当前参考段 + 前段已发布音视频尾部
                 ↓
       H3 Ref2VA / Motion Context
           全片按依赖顺序生成
                 ↓
       子段拼回 → 恢复原速与帧数
                 ↓
       挂回完整原音乐 → 原片检查
                 ↓
       可选 RIFE 60fps / RTX VSR
```

这里有两次用途不同的 RIFE：生成**之前**为慢速参考补充中间运动帧；生成**之后**可选提升交付帧率。只改 FPS 或重复原帧，不等于第一步的真实插帧。

## 开始前准备

1. **角色包**：至少一张清楚、无遮挡、服装可辨认的角色图；写明发型、配色、配饰和服装不可变项。历史银狼路线用一张角色图，不把三视图列为已实测前提。多视图可用于辅助准备，但要单独验证输入顺序和一致性。
2. **驱动片**：单一主要表演者、动作和切点可定位；提供拥有使用权限的视频。高速剪辑、严重遮挡和背景文字会增加失败风险。
3. **音乐**：一条与源时间线对应的完整音轨。参考片内的音轨可供同步参考，最终仍从权威源回装，不依靠 H3 生成一条相同音乐。
4. **执行环境**：自托管 ComfyUI、H3 Ref2VA 配套模型、支持联合音视频及 Motion Context 的实际实现、RIFE、FFmpeg/ffprobe；RTX VSR 仅为可选后期。硬件和依赖边界见[运行契约](workflows/README.md)。
5. **项目目录**：在用户工作区保存素材、参考子段、提交图、候选、记录和导出，不在模板安装目录内写运行结果。

## 制作步骤

### 1. 锁定参考与时间线

记录视频与角色图 SHA-256、源 FPS、解码帧数、尺寸、SAR、音轨和切点。采用半开帧区间 `[start, end)`，每段都能回溯到同一源片；片段秒数仅用于显示。

以动作循环、换装或镜头结构划分制作段，再将制作段拆为推理子段。**镜头、制作段、H3 任务不是同一概念。** 银狼最终沿参考表生成 14 个制作段，内部共 27 个 H3 子段；没有照搬「只生成几套循环后复制铺满全片」的省算力方案。

### 2. 做真正的半速动作参考

先把参考规范到目标基础 FPS 和画幅，保留比例；不得静默拉伸或裁掉构图。历史配置为 1344×768、24fps。

对每个制作段用 RIFE 生成两倍帧数的中间运动序列，再按基础 24fps 播放，得到 0.5×参考。若音频参与参考，同步做半速处理；它不是最终音轨。检查 RIFE 实际帧数，不能假定任何实现都恰好输出 `2N`。

慢速参考使 H3 在更长的生成时间内处理原来的运动，这是此配方的设计意图；不是已通过受控实验测得的质量提升结论。代价是需要生成更多帧。

### 3. 绑定角色、当前动作和续接来源

第一子段使用角色图与该段驱动视频进行 Ref2VA。后续子段除这些参考外，额外使用**紧邻前一子段已发布的慢速音视频尾部**重建联合音视频 Motion Context。不能用恢复原速后的片段作慢速链上下文，也不能随意取未发布的物理 latent 尾部。

整条链只保留一个顺序：`seg01/A → seg01/B → seg02/A → … → seg14/A`。不能把两个互相独立生成的分支直接拼接后称为整链续接。

使用[参数化提示词](prompts/ref2va.template.txt)，把角色、当前子段时长、背景保留目标与音频用途写清。每次保存模板稿与实际提交稿；源片等长属于目标，实际长度由工作流和解码检查保证，不能靠 prompt 中的 “exact” 保证。

### 4. 串行生成、检查与返修

历史基线：H3 Ref2VA、20 steps、`res_multistep` / `simple`、原生 PyTorch Attention、不使用 Turbo LoRA、SageAttention 或 EasyCache。参数见[profile.json](profile.json)。

提交前检查实际 `/object_info`、权重、节点和参考连线；提交后记录 Prompt ID，使用队列、History 和采样进度判断状态。网络断开先查询旧任务，禁止盲目重复提交。前段输出有效后才推进下一段。

对每段检查身份、服装、背景亮度、动作、切点与边界，并另做帧数、音轨、SHA 和完整解码检查。技术成功不等于语义通过。明显失败段不得成为后续上下文或直接送去超分。

重做时保留旧稿、旧 Seed 与旧产物，创建新版本。前段改变后，其后续生成依赖失效，需要重新评估或重跑依赖链；本模板的「局部返修」不保证只重做一个文件就能接回整片。

### 5. 先拼子段，再恢复原速

把同一制作段的慢速子段按序拼回，去掉**有记录的尾部保持填充**，然后做预先定义的 2×速度复原，使其回到该制作段的源帧数与基础 FPS。历史实现是在已合并的慢速序列中保留偶数帧，不能在两个奇数长度子段中分别抽取，否则会改变边界相位。

这里的速度复原是制作设计的一部分，**不是为掩盖接缝错误而对任意成片全局抽帧或拉伸**。Motion Context 的隐藏前缀必须已在工作流内正确去除，剪辑阶段不得二次删头。具体帧数例子见[证据与时间线](evidence/README.md)。

### 6. 回装音乐，原片通过后再做交付增强

按原帧表连接恢复原速的制作段，视频总帧数必须等于目标。挂回一条完整权威源音轨，而不是拼接 H3 每段生成的音乐。

若要求音乐字节级保留，使用兼容容器的音频流拷贝并比较音频基本流 SHA；不要随手加 `-shortest`，它可能截去 AAC 尾包。容器时长与视频帧时长的微小差异单独记录。

原片通过后可选 RIFE 到 60fps、RTX VSR 3× ULTRA、H.264 目标码率 100Mbps，音频流拷贝。它是后期增强，不是 H3 原生 4K，也不能修复已经生成错误的脸、动作或背景。

## 交付什么

- 独立成片与未超分原速母版；参考／生成对比视频按需制作。
- 角色绑定、源帧区间、慢速子段映射、模型／节点版本和实际提交图。
- Prompt ID、Seed、输入输出 SHA、解码检查与接缝／人物检查记录。
- 失败原因、重做关系、费用或 GPU 占用耗时；未知项写未知。
