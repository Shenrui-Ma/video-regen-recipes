# 默认爻光剪辑与交付

## 1. 不推理，直接复用现有画面

本包的四个剪辑源已经选好：前两段各158帧，后两段为完整canonical解码、各175帧。它们不是后两段各141帧的发布副本，不能交换。

把 `TEMPLATE_DIR` 设为本模板目录，`PROJECT_DIR` 设为用户项目。需要已安装的 Python 3、FFmpeg/ffprobe 和 libx264。

```bash
python3 "$TEMPLATE_DIR/scripts/render_default.py"
python3 "$TEMPLATE_DIR/scripts/render_default.py" --execute --output "$PROJECT_DIR/yaoguang-edit.mp4"
```

第一条只校验文件哈希、实际帧数、尺寸、帧率和音乐长度；第二条才重新剪辑编码，**不调用 H3、不占用生成额度**。要换音乐，加 `--music` 和本机音乐文件路径；音乐至少26.45秒。输出文件必须不存在。

脚本保留默认时间线和最后0.5秒音乐淡出，输出1344×768、1587帧、60fps、AAC音乐。编码采用通用libx264/CRF18，属于公开版重新导出，不承诺和历史成片字节相同。已有源文件不改动。

## 2. 默认时间线怎样组成

历史PR采用后段覆盖前段尾部。等价的顺序剪辑如下：先把每个源片用 `fps=60` 重采样，再取对应前缀拼接。

| 素材 | 源帧数 / 24fps | 保留的60fps区间 | 在最终时间线 |
| --- | ---: | --- | --- |
| part-01 | 158 | [0,395) | [0,395) |
| part-02 | 158 | [0,373) | [395,768) |
| part-03 canonical | 175 | [0,382) | [768,1150) |
| part-04 canonical | 175 | [0,437) | [1150,1587) |

总计26.45秒，比约24.5555秒的原驱动长。这里是已校准的默认剪辑，不声称严格同源等长。

`fps=60` 会重复／丢弃帧，不产生运动估计中间帧。历史另有 RIFE 处理的旧分支，但它不是默认成片来源。不要在本版说明中标成RIFE插帧。

## 3. 新角色不能直接套默认切点

默认素材之间曾测出10帧和22帧复制样本，但PR覆盖点又使用60fps的22帧和55帧，含非整数24fps边界。它们来自具体画面，不是通用context裁切公式。

换角色后先逐帧确认动作连续、重复与缺口，记录新的选源和切点，再构建新时间线。不要把offset9/21误当覆盖样本10/22，也不要把7帧参考重叠当所有输出的删头数。默认脚本用素材哈希锁定，拒绝把不同生成结果硬塞进旧剪辑。

## 4. 音乐与可选增强

最终音乐是一条独立轨道，截取 `[0,26.45)`、在25.95秒开始0.5秒淡出，完全替换分段原音轨。音频经过AAC重新编码；只在之后真正使用流拷贝时才能声称音轨字节保持一致。这不是AI翻唱。

- **超分**：默认先交付基础版。历史可选RTX VSR 3× ULTRA，输出4032×2304、60fps，32帧分块。按当前节点和设备重新检查，保存每块帧区间与哈希；不重做已经合格的块。
- **竖屏**：历史从4032×2304居中裁成1728×2304，`crop=1728:2304:1152:0`，并非人物跟踪或背景扩展。新人物先看构图，避免裁掉动作。
- **RIFE**：若用户另行要求运动插帧，作为新版本执行并标明，不改写默认版的生成记录。

最后核对帧数、FPS、SAR、音轨和完整解码，再看接缝、人物及音乐同步。保留基础母版、选片表和可选增强版；尚未目视／听审就标记待检查。
