# 准备图片与声音

视频使用本地 H3；辅助素材不限工具，可以用 ComfyUI、NovelAI、GPT Image、本地或在线语音服务。

## 图片

选择[参考图 Skill](../skills/)：ComfyUI、GPT Image 2 high 或 NovelAI。先完成单张验证，再准备角色图、场景和镜头关键帧。

- 从清晰的角色图开始，按镜头补齐服装、表情、场景或关键帧。
- 标明每张图用于身份、画风、动作还是首尾／中间帧，并确认所用工作流支持该用途。
- 逐次绑定提示词里的“图1、图2”与实际文件，编号不能跨任务照搬。
- 分开保存作者原提示词与实际提交稿，记录素材来源和版本。

### 生图后端怎么选

改图、换装、去背景或准备首帧前，先按用户的 **Agent 产品与模型 provider** 决定生图方式，默认“能走 CLI/API 就不走网页”：

- 用户在用 **Codex**，或用 Hermes / OpenClaw 这类开源 Agent 但**订阅走 Codex / GPT** → 优先 **GPT Image**：先试宿主内置 `image_gen`，不可用时用 `imagegen` 技能 CLI（需 `OPENAI_API_KEY`）。
- **其它 provider** → 先看它的 API 有没有视觉能力：有视觉就能承担看图与验收；不能出图时再往下找。
- 看用户**已经登录的 chat**，优先级 **GPT → Gemini → 豆包**；未登录时先把登录页打开给用户，等他登录（不索取密码、不代登录、不碰 cookies）。
- 都没有 → **本地 ComfyUI**；再不行 → **用户自备图片**。

完整的决策顺序、后端能力对照表，以及**豆包实测链路**（上传/取回命令、提示词模板、坑表）见 [生图后端怎么选](image-generation-backends.md)。

## 声音

- 分清临时配音、音色／表演参考、最终对白、环境音与音乐。
- 标明说话者、用途及文件；声音参考不一定会直接成为成片音轨。
- “无背景音乐”不等于静音。只有混合音轨时，换音乐需要先处理原音轨中的对白和音乐。
- `detailed_description` 用于描述画面、动作和对白，不是禁止字幕开关，详见[官方规范](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)。

## 公开素材

只上传自有或允许再分发的图片、录音和音乐；否则提供来源链接与输入说明。
私人角色库、账号密钥和 cookies 留在用户工作区，不要提交到仓库。

## 素材获取：先自己拿，拿不到才交给用户

顺序固定，前一步没做完就不要跳到下一步；**不要因为麻烦就跳过自动路径**：

1. **用户已有的文件**——直接登记来源，不要重复下载。
2. **公开可校验的下载**——HTTPS 直链 + 固定版本/哈希（媒体库、发布页、模型仓库）。
3. **自动抓取**——不需要登录的公开页面优先自动化，参考视频用[参考视频获取 Skill](../skills/reference-video-fetch/SKILL.md)；模型发布页、GitHub Release、Hugging Face 仓库同样先尝试自动获取。
4. **确实拿不到时才请用户手动下载**——需要登录、验证码或会员清晰度，区域限制，站点拒绝自动化访问，或分享链接已失效（包括夸克、百度、蓝奏、Google Drive、OneDrive、Discord 附件这类网盘与分享页）。

把问题交回用户之前，先做三件事，别把能自己解决的推给用户：

- 换一个等价来源（官方发布页、作者主页、镜像或 Release）；
- 确认不是本地工具缺失（`yt-dlp`、`ffmpeg`、网络）或一次性抖动，必要时退避后重试一次；
- 把失败原因原文留档，和链接一起交给用户。

处理网盘与登录墙资源时：

- **让 Agent 打开该页面**（有浏览器能力时）或把链接交给用户，并说明为什么需要他手动完成；不代登录、不代转存、不猜直链。
- **给清单，不给模糊请求**：要下载哪个文件、放到哪个绝对路径、期望的字节数与 SHA-256。
- **下载后先校验再继续**：大小或哈希对不上就停下重来，不要拿近似文件顶替；校验通过后回到原来的自动化流程继续。
- **如实记录**：来源链接、上传者、获取日期、文件哈希、许可状态，并标明这是“用户提供”。不要把网盘链接写成“已验证可获取”，也不要把私人分享链接当公共素材写进模板。
