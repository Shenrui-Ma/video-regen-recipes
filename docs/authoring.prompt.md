# 将制作经验封装为可贡献的视频模板

你现在是 Video ReGen Recipes 的模板制造者。请把我提供的视频、制作工程、提示词、工作流、脚本和制作经验，整理成其他创作者可以交给自己的 Agent 使用的公开模板。

目标不是只写一篇教程、复制一份 SKILL.md，或重新剪出我的旧视频，而是补齐“作者做成功一次”和“另一个用户用自己的素材做出一个版本”之间的步骤：让 Agent 知道需要什么、怎样取得和绑定素材、怎样调用工具、怎样剪辑、失败后如何继续，以及哪些结果已经验证。

例如：“把我们刚才做好的【作品／项目】整理成 Video ReGen Recipes 模板，让其他用户可以替换【角色／场景／台词／歌曲／产品等】继续制作。相关资料在【本次附件或项目目录】。”不要求我先填一张完整的技术表；能从本次提供的资料和已授权项目中读取的信息，你自行整理。

## 1. 确认资料、仓库和本轮范围

先读取我提供的资料、本次对话中已有的制作过程，以及我明确授权访问的相关工程。可以追踪这些资料明确引用的依赖；不要扫描无关私人目录、其他项目或全部聊天历史。无法访问的资料记录为缺失，不根据文件名猜内容。

在开始修改前，阅读当前仓库的以下内容，并记录所用 commit 或工作副本状态：

- `README.md`、`CONTRIBUTING.md`。
- `docs/template-format.md`、`docs/template-index.md`、`templates/catalog.json`。
- `docs/testing/reproduction.prompt.md`，理解最终要交给独立测试者验证什么。
- `templates/character-short/bit-by-bit-heartache/` 的 README、SKILL、profile，以及与本次相关的素材清单、工作流／环境引用、执行脚本、恢复、分发和验证说明。

Heartache 用来参考完整性，不是要求所有模板使用它的模型、续接方法、帧数、分辨率、目录数量或安装流程。再按本次题材读取最接近的现有模板和公共 Skill；不必一开始加载全仓所有长文档。文档、历史记录与当前脚本冲突时，列出具体位置和证据，不能静默拼成一套从未成立的流程。

优先在已有仓库工作区制作。没有工作副本时，在本次允许的位置获取公开仓库，或先交付独立候选目录并说明尚未接入索引。不得覆盖已有修改、切换他人的工作分支或改动无关文件。只有聊天能力、不能写文件时，按路径输出完整文件内容，并明确没有落盘或执行。

**本轮默认是模板制造与离线验证。** 可以在授权范围内查阅官方资料、补写脚本、修复问题；关键补救必须沉淀进公开模板。下载大文件、安装运行环境、GPU 推理、付费调用、上传素材及外部发布遵循本次明确授权，已有授权不重复索取。未授权的操作停在计划，不影响继续完成可做的整理。只在资料和环境无法解决、且确实影响下一步时询问必要问题。

## 2. 提炼制作配方，不复制个人工程

先写清模板的效果、输入、步骤、配置和验证范围，回答以下问题：

| 要说明的内容 | 要落实到模板中的信息 |
| --- | --- |
| 做什么 | 成片类型、典型使用场景、一句话使用示例，以及能查看的效果证据 |
| 保留什么 | 构图、动作、运镜、节奏、风格、角色关系或声音等效果成立的关键条件 |
| 可以改什么 | 角色、服装、场景、台词、画风、配乐、产品等变量，以及修改后的限制 |
| 怎么开始 | 用户最低需要提供什么，哪些素材能由 Agent 准备，哪些必须由用户提供 |
| 怎么完成 | 主制作路线、输入到成片的步骤、后期、检查与交付物 |
| 证明到哪里 | 作者历史成功、本次改造、自测与独立复现分别做到哪一步 |

选择有真实依据的一条主路线，先把它写完整。不为凑兼容性增加多条未实现路线，也不把参数替换说成后端迁移成功。按当前贡献范围处理：视频生成以 ComfyUI／H3 为重点，图片和声音按对应能力选择工具；纯剪辑、音频、HTML／SVG 等流程按自身需要组织，不强行加入视频推理。作者原方法与本仓库接入方案不同时，保留原方法记录，明确迁移了什么及尚未验证什么。作者原始效果配置作为基线保留，普通创作按第5节选择本地可用的运行配置。

区分“保留观感与节奏”“跟随动作和运镜”“逐帧仅替换主体”，只承诺实际能做到的程度。固定 seed 或一个成功样片，不足以承诺跨环境像素一致。

先检查是否已有同类模板。仅换示例角色、换标题或增加一套素材，优先作为已有模板的示例或变体；有独立制作方法、镜头节奏和执行入口时，才建立新模板或子模板。保留原作者、整理者和贡献者的真实署名，不把模板参考对象的作者复制成本次作者。

## 3. 按现有架构落盘

新模板通常放在 `templates/<分类>/<模板目录>/`。沿用现有分类、稳定 ID 和文件约定，不另建一套与 catalog 不兼容的模板体系，也不把占位目录视为已经可调用的公共能力。

| 文件或目录 | 职责 |
| --- | --- |
| `README.md` | 给人看的效果、输入要求、一句话入口、最短使用方法、可改范围与状态 |
| `SKILL.md` | 给执行 Agent 的触发条件、能力要求、执行顺序、通过条件、恢复与交付 |
| `profile.json` | 当前索引要求的元数据、稳定 ID、状态和真实入口路径；其他运行字段按需增加 |
| `sources.md` | 作者、作品／教程／代码来源、版本、许可依据与尚未确认的事项 |
| `prompts/`、`examples/` | 按需保存提示词模板、可填写配置和示例；区分原稿与实际提交稿 |
| `references/`、`workflows/` | 按需保存详细方法、固定版本引用、参数说明和预览图 |
| `scripts/`、`tests/` | 按需提供实际执行或校验工具，以及覆盖其关键行为的测试 |
| `assets/` | 小型可公开素材、素材清单与获取说明，不存私人运行产物或模型权重 |
| `evidence/` 或验证说明文件 | 历史证据、本次检查、真实运行、失败与未验证范围 |

这不是要求每个模板生成全部目录；没有对应职责的文件不要创建。已有模板更新时，尽量沿用其结构。

遵循现有分工：Recipes 维护拍法、输入绑定、提示词、时间线、模板执行和验收；公共图像与剪辑能力优先引用 `skills/` 中真实存在的实现；通用 ComfyUI 图和环境参考优先关联 `shenrui-comfyui-toolkit`。参考 Heartache 当前的 `workflow.lock.json` 与 `environment.lock.json`，但核对它们在本模板中各自应承担的职责，不照搬字段值。

固定工作流内容与记录已知环境，不等于强制所有用户重装作者的整套环境。共享能力在源仓库维护一份。确需新增 Toolkit 工作流、环境资料或媒体库资产时，准备对应变更与跨仓依赖说明；尚未公开的文件不得伪造为可下载链接，不擅自推送或上传其他仓库。

## 4. 把素材准备写成真正的入口

对每种必需输入，明确用途、取得方法、最低要求、预处理、绑定位置和验收方法。角色身份图、画风图、动作驱动、首尾帧、音色参考、最终对白和 BGM 不能仅统称为“参考素材”。

用户输入优先，其次是当前项目已确认素材。只给角色名字时，模板应说明如何查找可靠参考或调用已有参考图 Skill，不一律把上传立绘当成必答问题。用户已经提供可用图片时，不强制再走生图；无需去背景、多视图、声音或其他可选环节时，不额外部署。没有可靠来源或缺少用户专有素材时，再报告具体缺项。

指定角色、语言、服装或其他要求不能被默认示例覆盖。需要备用素材时写明触发条件；历史人物、原视频和旧成片不作为新角色任务的自动兜底。

对固定公开素材建立清单，记录真实来源、固定版本或 revision、相对路径、字节数、SHA-256、用途、必要媒体规格、是否默认获取及许可状态。参考 Heartache 当前的素材库引用方式；大媒体通过明确的外部素材库或发布渠道按需获取，不塞进 Git 历史。没有再分发依据时，保留来源与用户自备说明，不因放到外部站点就当成可以发布。

将运行必需素材、可选预处理素材、历史演示素材分开。缺少用于执行的驱动母片时，不能只给原视频网页然后让使用者猜裁切方法。提供可执行的裁切／转换步骤，记录原件到处理后输入的关系；校验值拿不到就标未核验，不编造。

确需下载工具时，支持复用已验证文件、下载后核对大小和哈希、临时文件完成后再正式落盘。失效、截断、哈希不匹配或无权限时明确失败，不悄悄换来源或拿旧文件顶替。

## 5. 写出能执行的主流程

`SKILL.md` 使用清晰的 `name`、`description` 和精简正文。描述的是未来用户如何用模板制作，不是本次作者如何提交贡献；不绑定某个 Agent 品牌才有的工具名。需要宿主专用操作时，单独说明并限定验证范围。

每一步都写到以下程度：

> 输入是什么 → 读取哪份说明 → 执行什么命令或工具操作 → 参数怎样取得 → 产生什么文件或任务 ID → 怎样检查 → 失败后怎么办。

正文给出顺序与判断，细节放在直接可达的引用中。不要用“自行配置环境”“按需修改工作流”“解决兼容问题”“适当剪辑”替代关键步骤。需要作者临时写过的脚本、私有节点或补丁时，提供可公开实现、固定版本引用或明确的缺口；只写节点名称不算提供依赖。

**环境与模型。** 默认复用用户已有的可用环境、模型和缓存，优先尽快跑通生成链路，不要求无故升级、降级或对齐历史版本。区分正常运行所需的检查与出现缺项／报错后才用的深度诊断；不要把完整环境审计、全量模型哈希扫描或重装作为所有任务的强制起点。新建环境使用独立目录，不覆盖共享安装。

先快速盘点本次实际使用的模型目录和缓存。用户未明确指定具体权重、精度或要求严格复现原配置时，本地已有兼容、可运行的量化版本或少步 LoRA，就优先用现有组合执行，即使作者原工作流使用非量化模型、未加载少步 LoRA；两者可以分别使用，不要求凑齐。没有可用的量化版本或少步 LoRA，但已有原版／满血模型且能够运行，就直接用原版，不为追求加速额外下载或等待。只有本地没有可用方案、确实需要下载模型时，再简要说明可选的效率方案与原版方案、所缺文件、下载量及新增占用，让用户选择；已有明确选择与下载授权则沿用。路径无法访问不代表模型缺失，缺少可选加速文件也不代表必须下载。

用已有配置、文件元数据和发布说明核对模型家族、生成模式、加载器及 LoRA 配套条件；少步 LoRA 按其适用说明配置步数、强度和采样参数，不能只凭名称混用或任意减少步数，也不为选型先跑一轮全面对比。将选择规则、必要参数和加载分支落实到模板及脚本，不让历史精度、步数或“必须无 LoRA”的校验无条件阻断兼容方案。保留动作参考、音频、续接等本模板必需能力，并记录实际模型、精度、LoRA 和参数。运行完成后简短说明“这次使用了本地已有的效率方案，优先跑通流程”，按实际选择补充即可；不冒称与作者效果完全一致或已测得加速倍数。

**工作流与绑定。** 给出实际可执行的 API 图或可验证的固定引用，记录图版本和哈希、有效分支、参数位置、输入输出节点及所需模型／节点。GUI 预览图不冒充 API 执行图。图号、角色槽、音频编号和本次上传返回的文件名逐项对应；提示词写了“图1”不等于图片已接入。模型身份、精度和模式根据真实资料核验，不仅凭名称猜测。固定引用保留为源图；按选定运行配置绑定模型、加载分支和采样参数，另存实际执行图及其哈希，不覆盖源图或混淆两者的验证记录。

**参数化。** 把作者人物、私人路径、主机地址、输出位置和旧任务 ID 改成明确的用户输入或运行时配置，同时保留效果所需的真实参数与推导方法。给出必填项、默认值、范围、单位、示例及不支持值的错误。可填写模板允许占位符，实际执行前必须检查全部绑定；区分效果所需的固定条件与运行配置可调整的精度、LoRA、步数等，不要把个人测试值提升为通用硬件保证。

**检查与视觉。** 参考图、分镜和预览的视觉检查以少量关键检查为主，能合并就合并；同一素材没有变化时复用已有结果，不逐帧或逐镜头反复询问视觉模型，也不为追求完整评分拖延生成。已知没有视觉能力时直接跳过辅助视觉调用；能力明显不足、返回内容与已知信息明显矛盾或不可信、视觉额度耗尽／限流时，停止重复调用，记录该项未检查或待确认，按用户输入、已有可靠资料及技术检查结果继续生成和后期，不要求先换模型或等额度恢复。一次温和提示即可，例如：“这次视觉检查暂时不太顺畅，我会先继续生成，画面细节留待确认；之后使用视觉能力更稳定的模型，检查可能会更充分。”不要把不可信的视觉判断写入角色设定或据此修改、重做素材。

在输出模板的通过条件和实际调用的检查分支中落实上述处理，不把辅助视觉检查设为必须通过的门槛。文件读取与解码、输入绑定和工作流可执行性等必要技术检查照常进行；仍然缺少必需输入、权限，或用户明确要求先确认某项结果再继续时，停在对应步骤。继续制作不等于视觉验收通过，成片可以交付并注明画面待确认，不因缺少辅助视觉再次卡住交付。

**执行工具。** 重复、易错且可以确定性完成的处理，尽量落实为小脚本或已有工具调用。说明工作目录、路径基准、依赖、命令和结果。计划／静态检查与真实执行分开，命令名称可以沿用已有实现，不要求统一改成某个 CLI。默认检查不得暗中调用付费服务或启动 GPU 任务。

**运行位置。** 默认本地；用户使用自托管远程环境时，明确连接、输入传输、输出取回及文件系统关系。不要把客户机路径直接当服务器路径，也不要把只支持共享本地文件系统的 runner 宣传成已支持任意远程服务。

## 6. 保留拍法、时序和后期细节

分开编号镜头、生成任务与剪辑片段，记录对应关系和明确的选用版本。一次生成可以包含多个镜头，一个长镜头也可以由多次生成组成；不要用文件名排序代替选片清单。

按本模板实际方法补齐以下内容，不相关的项目跳过：

**生成与衔接：** 独立片段、硬首尾帧、参考条件和 latent 续接必须分清。真正需要续接时，写明前驱输入、保存／读取方式、窗口来源、参数单位、裁切位置和恢复方法。分段受硬件容量影响时，提供容量取得与校准方法，分别说明固定规格和可调整段长；不得照搬 Heartache 的段数、`17k+5` 网格或 context 数值。减少段长不能被当成解决模型最低加载容量的万能办法。

**时间线：** 明确源 FPS、生成帧数、实际解码帧数、发布帧区间、变速、转场重叠和最终时长。使用可核对的帧／采样区间，说明端点是否包含，例如 `[start, end)`。上下文裁切只做一次；不为凑整数时长静默丢帧，不把改 FPS 或重复帧说成插帧。

**声音：** 区分参考声音、模型原生音轨、最终对白、环境声和配乐。明确保留、去除或混合哪些音轨，音乐从哪里开始、如何连续铺设、跨段如何衔接和淡出。音轨太短不能静默截短视频；没有生成或取得声音时如实记录。声线转换、训练及歌词字幕按对应模板的方法与验收要求处理，不强行绑定 MV。

**后期：** 提供实际裁切、拼接、布局、字幕、混音和导出方法，写明关键参数与素材顺序。人工选帧、听审或剪辑操作如果仍然必要，要明确停点和操作标准，不能宣称已自动化。插帧、超分和原生生成规格分开记录；HTML／SVG 等流程按其自身时间控制与渲染方式实现。

**定制：** 说明换角色、改单镜头、改台词或只换音乐时，哪些输入需要更新、哪些阶段可以复用、哪些连续性需要重新检查。已有成片重剪单列入口，不把重剪旧片当作从新输入完成生成。

## 7. 把恢复规则写进说明与实现

本次用户项目与模板源码、作者原工程分离，输入原件只读，输出使用独立目录和新版本。为任务保留输入、实际参数、图版本、状态、任务 ID、选用产物及哈希；不凭文件存在、修改时间或相似文件名判断成功。

对存在异步提交或多阶段执行的模板，至少覆盖：

| 情况 | 应有行为 |
| --- | --- |
| 已有任务 ID，连接中断 | 查询并恢复同一任务，不默认重新提交 |
| 提交回执丢失、结果未知 | 保留未知状态并核查原任务，无法判定时停止自动重试 |
| 采样成功，解码或后期失败 | 使用已经保存且核验过的阶段产物恢复；支持从 latent 解码时不再采样 |
| 某一镜头失败 | 保留成功项，只处理失败项及受影响的后续依赖 |
| 输入、工作流或前驱结果改变 | 显式失效对应下游结果，不继续复用旧成功记录 |
| 用户要求停止 | 阻止后续提交；取消服务中任务前确认归属，不清空共享队列 |
| 辅助视觉不可用、结果不可信或视觉额度耗尽 | 停止该项重复检查，记录待确认；必需输入和执行条件具备时继续生成与后期 |
| 达到任务总预算、生成预算、重试或时间上限 | 停止相关新增任务并保留记录，不无限重试；仅视觉额度耗尽按上一行处理 |

对关键状态采用防重复执行和安全写入措施；实现需要时使用任务锁、原子落盘与哈希核对，不为简单模板额外制造通用调度平台。记录重试条件和上限，区分查询重试、下载恢复与重新生成。未实现的恢复能力明确标出，不只在文档中承诺。

用户只要求首段预览时，不顺带生成全部；要求前几段累计版时，按整条时间线交付，而不只返回最后一段。

## 8. 处理公开化与分发边界

分别记录原创说明／代码、第三方代码、模型权重、图片、视频、声音、音乐和字体的来源与许可。代码许可不覆盖其他资产，署名、非商业或公开可访问也不代替具体许可依据。第三方代码需要保留原许可；补丁记录适用版本、改动、来源及许可，不发布来历不明的私有实现。

原始日志和工程可以在授权范围内用于制造，但公开版必须去掉密钥、cookies、账号标识、聊天路由、私人主机、绝对路径与未获准公开的素材。去元数据另存分享副本，不改写用于复现的原件；不能把去元数据说成取得了再分发权。

明确本模板是“依赖完整仓库使用”还是“可独立安装”。前者保留正确相对路径并说明需要完整目录，不能让用户只复制 SKILL.md；后者必须包含或能按固定引用取得全部执行必需的说明、脚本、图和配置。独立安装不等于完全离线，更不等于自带模型、算力或账号权限。

需要独立包时，检查打包清单、逐文件哈希和安全路径，排除密钥、私人日志、虚拟环境、缓存、运行结果和模型权重。媒体按约定外置，缺少的必要资产有明确获取方式。按模板实际内容保留 HTML、JavaScript、SVG 等必需文件，不盲抄 Heartache 的打包白名单。解压到新目录复查入口和依赖，不能只在作者原工程中测试。

## 9. 制造自测与独立复测分开

先完成制造自测。发现缺口可以查资料、写代码、修正方案，但必须记录来源和改动，并把必要解决办法写入模板；不能把“Agent 临时救场”藏在成功结论后面。

按实际能力分层验证，并分别记录：

| 验证层次 | 能说明什么 |
| --- | --- |
| 文档与静态检查 | 入口、字段、引用、占位符、路径和参数规则可检查 |
| 离线脚本测试 | 参数绑定、时间线、错误处理、恢复状态等实现行为符合预期 |
| 合成媒体／模拟响应测试 | 对这些测试夹具的编解码、拼接或状态处理成立，不是实际模型生成 |
| 作者已有环境实跑 | 该环境、输入与本次模板版本的真实制作结果 |
| 干净环境或独立解包测试 | 只证明实际执行过的安装、获取与运行范围，不自动等于 GPU 推理通过 |
| 新会话或外部用户严格复现 | 仅按冻结模板完成了记录中的测试；技术与内容验收仍分别说明 |

有脚本时，为关键正确路径和失败路径添加测试，例如缺文件、错哈希、未绑定变量、时长越界、重复提交、未知状态恢复、前驱变更和覆盖已有结果。实现了自动模型选择或辅助视觉分支时，覆盖本地效率配置优先、仅原版可用时直接复用、无可用方案才请求选择下载，以及视觉不可用／不可信／额度耗尽时不重复检查并继续执行；没有实现自动化的，检查对应说明与实际操作是否一致。不能只测试“文件存在”；也不要求为不具备的能力编造测试。纯文档更新执行相应静态检查，不为凑数量创建无意义测试。

有授权且资源足够时，先运行能验证关键方法的小样本：续接模板至少验证首段加一次真实续接；独立镜头流程验证实际输入绑定与后期；音频流程验证短段与听审。需要证明换角或其他定制能力时，使用不同于历史演示的新输入。资源不足就明确未跑范围，不用 mock、旧成片或空白素材代替。

每份验证记录写清日期、模板版本、环境、Agent 与模型、实际运行配置（含精度、LoRA、步数及与作者基线的差异）、输入概要、命令、任务 ID、产物及哈希、耗时／开销、失败和人工介入；未知值如实记录。文件检查、完整解码、视觉检查和听审分开，没做的不得通过。辅助视觉未完成只影响相应验收状态，不自动阻断已具备条件的生成与交付；需要视觉结论时保留给用户或后续人工确认。历史证据保留对应版本，不能自动继承到修改后的模板或不同运行配置。

完成制造后冻结候选版本，再使用 `docs/testing/reproduction.prompt.md` 进行独立复测。测试前明确本轮验证的是默认模型选择流程、某个效率配置，还是作者原始配置；前两者按模板已经写明的选择与视觉降级规则执行，不算模板外补救，后者保持约定配置。各项技术和内容验收仍分别记录，不将视觉待确认写成通过，也不在运行中临时放宽测试目标。优先新会话，条件允许时由另一位测试者执行。无法获得独立上下文时只记录作者自测，并提供复测入口。严格复测中发现缺口先留证，修复另开制造轮次，固定新版本后重测；不得在同一轮边修边把结果判成独立 PASS。
